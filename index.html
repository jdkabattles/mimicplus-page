02 — Why you are buying it

Stop rewriting the client from memory.

  • You already have a session you are allowed to record. Hand-copying it into a client drops fields and hides breaks.
  • mimicplus keeps the proof: endpoints, auth, pagination, and the fields that came back.
  • The next recording is the review. If the API moves, the check fails before you ship the old shape.
  • Secrets never enter the spec. A bad password stays a rejected call, not a credential in the repo.

05 — What goes in, what comes out

You feed it a recording. It hands back a list and a way to call it again.

A child can follow this. You used a screen. The screen talked to another computer. The browser can save that talk as a file. That file is the only thing you feed mimicplus. It is called a HAR. It is a list of questions the screen asked and answers the other computer sent. Take the passwords and tokens out first. Use a recording you are allowed to make.

What comes out is four things. A written list of what that other computer actually sent. A copy of that list to hold against next time. A small program a coder can run to ask the same questions again. An alarm if next time a piece is missing or has a new name.

The alarm in the sample is simple. A page is gone. A price is gone. A price comes back in cents. An order total is gone. A grand total is added. $199 once. The next recording is another $199.
