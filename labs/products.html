API Contract Prompts

About 40 prompts for the parts of API work where a model helps most and where its mistakes are easiest to catch.

Planned sections

  • API design: resource naming, pagination and error-shape decisions, and turning a feature brief into endpoint proposals with stated tradeoffs.
  • OpenAPI authoring: drafting OpenAPI 3.1 from example requests and responses, filling in schemas, and tightening loose types.
  • Contract testing: generating test cases from a spec, including error paths, boundary values, and auth failures.
  • Breaking-change review: explaining a spec diff, classifying each change for client impact, and drafting migration notes.

Each prompt is meant to be used with a real spec or real examples you supply, and the output should be checked by a validator or linter. The OpenAPI guide shows the approach.

Static Product Page Kit

A plain-HTML template for one product page on GitHub Pages, with no build step and no framework.

Planned contents

  • A product page, a 404 page, and a policies page in plain HTML and one stylesheet.
  • A Content-Security-Policy meta tag that allows only same-origin scripts and styles.
  • Title, description, canonical, Open Graph tags, and Product JSON-LD you fill in.
  • sitemap.xml, robots.txt, and CNAME examples.
  • A slot for a hosted payment link (for example a Stripe Payment Link) as a plain link, with no embedded checkout script.
  • A setup checklist covering DNS and HTTPS. The GitHub Pages guide covers the same steps.
