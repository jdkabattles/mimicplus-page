Hidden-suite verification for agent-written code

Make the pass mean something.

Avcal-Agent is a judge and coach for AI agents that write code. You give it a task. An agent tries to write the code. Avcal takes a snapshot, runs it against hidden tests the agent never sees, in a sandbox, and returns only safe feedback. Then the agent tries again.

It is built for one job: if the signal can be gamed, the pass is worthless. Avcal closes those holes by design, and fails closed whenever anything looks wrong.

The loop

Think of it as an exam where the student never sees the answer key, the grader never talks to the student, and the exam changes every time.

  1. The agent writes code. It sees the task description and its own previous work, nothing else.
  2. The hidden suite is the answer key. The agent never receives it. It is masked in every sandbox.
  3. The verifier is the grader. Only the verifier judges. It owns all judging, and any protocol irregularity is a WORKER_FAULT and fails closed.
  4. Feedback is redacted. The agent gets hints and failures, never leaked values. Hints are linted for leaked values.
  5. Fresh seeds mean the hidden tests are rebuilt with new random cases on every iteration, so memorizing one seed does not help.
  6. Holdout seeds mean a pass must be confirmed on seeds the agent was never scored on, so overfitting one seed does not count.

Two extra checks keep the claim honest. Preflight proves your hidden tests actually discriminate: they must accept the correct reference solution and kill mutants, including a hard-coder that just memorizes the public examples. Compare proves the feedback actually helps: it runs the same agent twice on the same seeds and budget, once with verifier feedback and once blind, and only claims a win when the confidence intervals separate.

Six commands

Start with the first three. They are safe, read-only, and teach you the system.

1. backends — what sandbox do I have?

python3 -m avcal backends

Inspects your machine. Reports the selected backend, its grade, and its limits. The grade tells you how strong the isolation is.

2. doctor — is this device ready?

python3 -m avcal doctor

One line per backend, OK or unavailable with a reason, plus limits, plus the strongest available grade. Run it first on any new machine.

3. preflight — do my hidden tests actually work?

python3 -m avcal preflight examples/interval_task

Reference must pass; mutants must fail, including the hard-coder. If preflight fails, do not run the agent loop yet. Fix the suite first.

4. verify — check one workspace, once

python3 -m avcal verify examples/interval_task ./my_workspace

The single-shot judge. Snapshots your workspace, runs it in the sandbox against hidden cases, and reports. No agent loop.

5. run — let the agent try, with feedback

python3 -m avcal run examples/interval_task --agent http

Iteration by iteration. Each attempt: snapshot, hidden verification, redacted feedback. Final verdict only after holdout seeds pass.

6. compare — does feedback actually help?

python3 -m avcal compare examples/interval_task --agent http --trials 10

Two solve rates with Wilson 95% intervals, feedback vs blind. Only claim a win when the intervals separate.

A worked example: the interval task

Task: write a function that finds overlapping intervals. The agent sees the spec and a few public examples. It does not see the hidden suite.

Preflight first: reference accepted, all mutants killed, including the hard-coder. That means your hidden tests are strong enough to trust.

Then the run. Iteration 1: the agent writes code, snapshot, hidden verification fails on some fresh cases, redacted feedback says which shapes failed, no values leaked. Iteration 2: the agent fixes it, passes the scored seeds. Then holdout: fresh seeds the agent was never scored on. If it passes holdout, the verdict is pass. If not, the verdict is fail — even if it passed the scored seeds.

Backends and grades

GradeBackendWhat you get

fileviewprootThe hidden suite is masked from the agent's code, plus everything below. Path masking only.
processNoneResource limits, scrubbed env, private temp dir, process-tree kill, hidden suite locked with mode bits.

Avcal never silently downgrades. If you ask for a grade it cannot provide, it refuses. On Termux (Android), namespaces and mounting are unavailable, so the phone uses the weaker backends — and every run prints the backend limits and records them in ledger.jsonl.

Fail closed, with a paper trail

  • Snapshot judged, not the live folder. The workspace is snapshotted before every verification, so the agent cannot change code mid-judgment.
  • ledger.jsonl — one JSON line per run, append-only. Backend actually used, limits actually enforced, seeds, verdict. If console output and ledger disagree, trust the ledger, and treat the run as suspect.
  • WORKER_FAULT — the run failed closed. Something violated the protocol. Do not retry it as a pass. Investigate, fix the agent or the task, then rerun.
  • Redaction by default. --unredacted is for you, the human, not for the agent. Never feed unredacted output back to the agent.

Known limits — stated, not hidden

  • No seccomp filter. The Linux grade is NAMESPACE, not a VM. Use --min-grade container with Docker for more.
  • DockerBackend and ProotBackend command lines are unit-tested; neither was run live in the build environment. avcal doctor probes them on your device.
  • HTTPChatAgent is tested against a local protocol server, not a live model. The compare verdict on a scripted fixture agent proves the plumbing, not model quality.
  • The interval suite does not check that the input list is left unmodified. The worker protocol returns values only.

Titles have no universal definition. What matters is the evidence behind the claim.

Why products fail without evidence

  • Building before validating — shipping a feature no one asked for, with no evidence anyone needs it.
  • Overbuilding — gold-plating a product before the core claim is proven.
  • Building in isolation — listening to what users said, not what they did.
  • Building for scale before proof — scaling a claim that was never verified.
  • Shipping unprovable output — an agent's answer with no trail behind it.

The antidote is evidence, not opinions: cheap experiments before expensive builds, assumption testing before building, and a gate that can say no.

How Avcal-Agent fixes it

  • Preflight is the gate that can say no. Your hidden tests must accept the reference and kill the mutants — including the hard-coder — or you do not run the loop at all.
  • Holdout kills overfitting. A pass must be confirmed on seeds the agent was never scored on.
  • Compare kills noise. Feedback only claims a win when the confidence intervals separate.
  • The ledger is the audit trail. Backend actually used, limits actually enforced, seeds, verdict — append-only, one line per run.

Four phases, four evidence gates

  1. Discovery: no requirement without evidence — the spec is what the agent sees, so keep it honest.
  2. Frontend: no UI claim without evidence — every number the interface shows must survive hidden verification.
  3. Backend: no API claim without evidence — every response the system returns is judged against cases the agent never saw.
  4. Ship, measure, scale: every iteration re-proven — fresh seeds, holdout, ledger, again.

Each gate is a positioning inference from the verifier contract, not a new feature.

Customers pay to make pain go away, not for elegance. In regulated work — legal, finance, healthcare, compliance — trust is evidence. A pass that can be gamed is worthless; a pass that survived a masked suite, fresh seeds, holdout, and a fail-closed verifier is a claim a customer can rely on. The final deliverable is a Revenue-Ready Digital Product that proves every claim — and Avcal-Agent is how the proof is earned.

Quick start

You need Python 3.9 or newer. Avcal uses only the Python standard library. No extra packages to install.

On Linux or macOS:

export PYTHONPATH=src
python3 -m avcal backends
python3 -m avcal preflight examples/interval_task

On Termux (Android, F-Droid build):

pkg update && pkg install git
sh termux/install.sh
avcal doctor

avcal doctor probes every backend on this device and lists its limits. Run it first on any new machine. It tells you what you actually have, not what the docs assume.

Run the full gate:

sh scripts/check.sh

Adding a task: create a folder, write task.json, write suite/suite.py with build(seed), add suite/reference/ and suite/mutants/* including a hard-coder, then run preflight. Fix the suite until preflight passes. Only then run the agent loop. Keep the spec honest — if the spec is vague, the agent will fail for the wrong reason.
